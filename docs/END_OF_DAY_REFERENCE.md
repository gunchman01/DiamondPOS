# End of Day reference and implementation scope

Primary references researched: Intuit, Point of Sale 7.0 User's Guide, Running Cash Drawer Reports / Sample Drawer Count Report (including printed page 455), https://http-download.intuit.com/http.intuit/OpenCms/sites/default/QBSupportSite/PDFs/POS70UG.pdf ; and Intuit Point of Sale 5.0 Getting Started Guide, Running the End-of-Day Procedure, https://http-download.intuit.com/http.intuit/OpenCms/sites/default/QBSupportSite/PDFs/POS50GSG.pdf . These are historical QBPOS guides, not a claim of exact equivalence to every later release.

QBPOS distinguishes a status report, per-workstation Drawer Count and all-store Store Close. Its documented drawer calculation uses opening cash plus paid-in less paid-out amounts, compares the count for over/short, and subtracts cash left to calculate the deposit. It also documents tender/credit-card breakdowns, discounts, receipt counts and noncurrency detail. Its wider closing procedure could include backups and financial exchange; integrated settlement belonged to its merchant service.

DiamondPOS implementation combines a store summary with optional per-till drawer counts. It reports supported recorded activity, saves numbered fixed snapshots and provides manual printing/export. It does not mimic unsupported gift-card media, discount reason codes, employee/shift login, denomination counts or integrated card processing. It uses a selected calendar date, not QBPOS's since-last-close state, and does not reset a register or mark the day locked.

A deliberate difference is dual date basis: business-date sales versus actual entry-day payment flow. DiamondPOS now allows past/future sale dates; using that date for today's physical cash reconciliation would be misleading. Actual void reversals use the void timestamp/till and original payment methods, with the payment-handling note visible for manual review. The completed outside-POS refund/cancellation is assumed, not verified by a payment processor. Manual cash adjustments are closeout inputs only and do not create money/accounting entries.
